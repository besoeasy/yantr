Linux Native Rootless Podman + Quadlet

Install Yantr

Yantr is designed for Linux. It runs 100% rootless inside Podman and is managed as a native systemd Quadlet service with auto-start on boot and named volume storage.

0

100% Rootless

Runs in user namespaces without root privileges. Zero daemon attack surface and no root access required.

Systemd Quadlet

Containers are first-class systemd services. Managed with standard systemctl and journalctl.

Named Volumes Only

Strictly isolates persistent app state inside named Podman storage with automatic SELinux :z labeling.

One-line Quick Install

Installs Podman (if not already present), configures rootless systemd lingering so containers start on boot, generates the Quadlet container specification, and starts Yantr.

curl -fsSL https://yantr.org/install.sh | bash

✓ openSUSE
✓ Raspberry Pi OS (64-bit)
Manual / Step-by-Step Installation

Prefer to inspect every command? Here is the complete breakdown of what the installer does under the hood.

1

Install Podman

Select your Linux distribution to install Podman using your native package manager:

sudo apt update && sudo apt install -y podman
sudo dnf install -y podman
sudo pacman -S --noconfirm podman
sudo zypper in -y podman
2

Enable User Lingering & Podman Socket

Enabling linger allows rootless systemd services to continue running across user logouts and start automatically on system boot.

loginctl enable-linger $USER && systemctl --user enable --now podman.socket
3

Create Quadlet Service Definition

Podman Quadlet reads declarative .container files inside ~/.config/containers/systemd/.

~/.config/containers/systemd/yantr.container
[Unit]
Description=Yantr Homelab App Store
After=network-online.target
Wants=network-online.target

[Container]
Image=ghcr.io/besoeasy/yantr:latest
ContainerName=yantr
Network=host
Volume=yantr_data:/data:z
Volume=%t/podman/podman.sock:/run/podman/podman.sock:z
AutoUpdate=registry

[Service]
Restart=always

[Install]
WantedBy=default.target
4

Activate Yantr Service

Reload the user systemd daemon to generate the unit from the Quadlet file, then start the service:

systemctl --user daemon-reload && systemctl --user start yantr.service
5

Open Yantr in Browser

Visit http://localhost:5252 (or from another machine on your LAN at http://<server-ip>:5252).

On your first visit, you will establish your operator credentials.

Managing Yantr via systemd

Because Yantr is registered with Quadlet, you have native systemd controls:

Check Status

Inspect running state, PID, memory, and uptime

systemctl --user status yantr

View Live Logs

Stream application output using journalctl

journalctl --user -u yantr -f

Restart Service

Restart Yantr without disturbing other containers

systemctl --user restart yantr

Trigger Auto-Update

Pull latest image and smoothly recreate container

podman auto-update

Uninstalling Yantr

Remove the Quadlet file and reload systemd to cleanly unregister the service:

rm -f ~/.config/containers/systemd/yantr.container
systemctl --user daemon-reload
podman stop yantr && podman rm yantr
# App data remains safe in named Podman volume: yantr_data
