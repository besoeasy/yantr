Why Rootless Podman Over Docker?

Unlike platforms that install a monolithic root Docker daemon and tamper with your host OS, Yantr uses 100% rootless Podman. Here is what that means in practice:

🛡️

Zero Host Root Privileges

Containers run inside unprivileged Linux user namespaces. Even if an attacker escapes a container, they have zero root powers on your physical machine and cannot read /etc/shadow or modify system binaries.

⚡

Daemonless (No Single Point of Failure)

Docker relies on dockerd. If it hangs or updates, all containers can die. Podman uses direct fork/exec via conmon. If Yantr restarts, your apps keep running without a hitch.

⚙️

Native systemd Quadlet

Containers are first-class systemd user services. Auto-starts on boot with user lingering (loginctl enable-linger), managed with systemctl --user, and logged to journalctl --user.

🧱

Untouched Host Firewall

Docker famously overrides host iptables rules, bypassing local firewalls like UFW without notice. Rootless Podman networks strictly inside user namespaces — never modifying host firewall rules.

Manual / Step-by-Step Installation

Prefer to inspect every command? Here is the complete breakdown of what the installer does under the hood.

1

Install Podman

Select your Linux distribution to install Podman using your native package manager:

sudo apt update && sudo apt install -y podman
sudo dnf install -y podman
sudo pacman -S --noconfirm podman
sudo zypper in -y podman
2

Enable User Lingering & Podman Socket

Enabling linger allows rootless systemd services to continue running across user logouts and start automatically on system boot.

loginctl enable-linger $USER && systemctl --user enable --now podman.socket
3

Create Quadlet Service Definition

Podman Quadlet reads declarative .container files inside ~/.config/containers/systemd/.

~/.config/containers/systemd/yantr.container
[Unit]
Description=Yantr
After=network-online.target
Wants=network-online.target

[Container]
Image=ghcr.io/besoeasy/yantr:latest
ContainerName=yantr
Network=host
SecurityLabelDisable=true
Volume=yantr_data:/data:z
Volume=%t/podman/podman.sock:/run/podman/podman.sock
AutoUpdate=registry

[Service]
Restart=always

[Install]
WantedBy=default.target
4

Activate Yantr Service

Reload the user systemd daemon to generate the unit from the Quadlet file, start the service, and enable the daily auto-update timer:

systemctl --user daemon-reload && systemctl --user start yantr.service && systemctl --user enable --now podman-auto-update.timer
5

Open Yantr in Browser

Visit http://localhost:5252 (or from another machine on your LAN at http://<server-ip>:5252).

On your first visit, you will establish your operator credentials.

Managing Yantr via systemd

Because Yantr is registered with Quadlet, you have native systemd controls:

Check Status

Inspect running state, PID, memory, and uptime

systemctl --user status yantr

View Live Logs

Stream application output using journalctl

journalctl --user -u yantr -f

Restart Service

Restart Yantr without disturbing other containers

systemctl --user restart yantr

Trigger Auto-Update

Pull latest image and smoothly recreate container

podman auto-update

Uninstalling Yantr

Remove the Quadlet file and reload systemd to cleanly unregister the service:

rm -f ~/.config/containers/systemd/yantr.container
systemctl --user daemon-reload
podman stop yantr && podman rm yantr
# App data remains safe in named Podman volume: yantr_data
